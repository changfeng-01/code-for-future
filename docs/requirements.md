# 基于Java的个人健康饮食记录与分析系统需求说明

## 1. 项目概述
- **目标**：提供面向个人的健康饮食记录、营养分析与统计展示工具，支持设置营养目标与历史数据查询。
- **技术栈**：Java 17+、JavaFX（桌面 GUI）、文件存储（CSV），无后端服务依赖，适合个人离线使用。

## 2. 核心功能
1. **用户管理与目标设置**
   - 登录/切换用户（本地用户列表，简化为选择用户名，无需账号体系）。
   - 录入并保存每日营养目标：热量（kcal）、蛋白质（g）、碳水化合物（g）、脂肪（g）。
   - 仪表盘显示目标完成度（进度条/环形进度）、目标达成提示。

2. **饮食记录**
   - 添加记录：日期、时间、食物名称、摄入量（克/毫升）、食物类别（主食/蔬菜/肉类/水果/乳制品/饮料/零食/其他）。
   - 记录营养数据：热量、蛋白质、碳水、脂肪；可由食物库自动带出或手动输入。
   - 支持修改、删除错误记录；删除时需确认提示。
   - 校验：必填项、数值非负、日期时间格式。

3. **营养分析**
   - 自动按日期汇总总摄入（kcal、蛋白质、碳水、脂肪）。
   - 与目标对比，生成文字报告：如“今日热量超标 10%/低于目标 5%”。
   - 显示各营养素占比（文本+条形进度）。

4. **饮食统计与趋势**
   - 周/月视图：各食物类别摄入占比（如蔬菜类 30%）。
   - 营养成分趋势：近 7 天/30 天热量、蛋白质、碳水、脂肪的变化（文本形式描述升降/波动）。

5. **数据查询**
   - 按日期查询饮食记录与当日分析结果。
   - 支持日期范围筛选与快速跳转到今天。

6. **数据持久化（CSV 文件）**
   - `user.csv`：用户名、每日目标（kcal、protein、carb、fat）。
   - `diet_records.csv`：日期、时间、用户名、食物名称、类别、摄入量、热量、蛋白质、碳水、脂肪。
   - 通过 Java IO 流读写；启动时加载，操作后即时落盘。

## 3. 数据结构
### 3.1 CSV 设计
- `user.csv`
  ```csv
  username,calorieTarget,proteinTarget,carbTarget,fatTarget
  alice,2000,70,250,60
  ```
- `diet_records.csv`
  ```csv
  date,time,username,food,category,amount,calorie,protein,carb,fat
  2024-05-20,08:30,alice,燕麦粥,主食,200,120,5,20,2
  ```

### 3.2 领域模型（建议类）
- `UserProfile`：用户名、目标值。
- `DietRecord`：日期、时间、食物、类别、摄入量、营养数据。
- `NutritionStats`：某日汇总的营养总量与目标对比结果。
- `FileRepository`：封装 CSV 读写；提供加载/保存用户、记录的方法。
- `AnalysisService`：计算汇总、目标完成度、超标/未达报告。
- `StatisticsService`：周/月类别占比、趋势文本生成。
- `Validation`：字段校验与错误消息。

## 4. 界面草案（JavaFX）
1. **登录页**：选择/输入用户名，若不存在则创建用户并提示设置目标。
2. **仪表盘（主界面）**：
   - 左侧：今日目标完成度（环形/条形进度）、文字分析。
   - 右侧：今日已录入列表（可编辑/删除），新增记录表单浮层/侧边栏。
3. **统计页**：
   - 周/月类别占比（列表/条形描述）。
   - 近 7/30 天营养趋势（文本描述升降/波动幅度）。
4. **历史查询页**：日期选择器，展示记录及分析摘要。

## 5. 流程与算法要点
- **新增记录流程**：
  1. 表单校验（必填、非负、日期时间格式）。
  2. 写入 `diet_records.csv`（追加）并刷新今日分析。
- **分析计算**：
  - 按日期+用户过滤记录，求和四项营养。
  - 计算完成度：`sum/target`；超标/不足提示（±%）。
- **统计计算**：
  - 类别占比：同一周期内按摄入量或热量求和再归一化。
  - 趋势描述：比较相邻日均值，输出“上升/下降/波动”文案。

## 6. 非功能需求
- **可用性**：表单错误即时提示；删除需确认。
- **数据安全**：本地文件写入前备份原文件（可复制到 `.bak`）。
- **扩展性**：
  - 可增设本地食物库，支持自动补全营养数据。
  - 可替换存储实现（如 SQLite）而不影响业务层。
